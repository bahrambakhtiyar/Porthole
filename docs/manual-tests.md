# Manual tests

The automated tests cover the server, the pages and a headless-Chrome run, but not real phones, real Wi-Fi or a real screen. These checks need a person. Each takes about five minutes. Write the date, the devices and anything odd next to each one.

Start Porthole on the PC (`python3 start.py`, `py start.py` on Windows, or an installed Linux package) and keep the phone on the same Wi-Fi.

## Phones

- [x] **iPhone, Safari:** scan the QR code. After Start sharing and **Allow** (Ask is on by default), a picture should appear within about 3 seconds. Done 23 Nov 2026: Ubuntu 26.04, the .deb and the AppImage, all fine.
- [x] **Android, Chrome:** the same. Done 23 Nov 2026: Ubuntu 26.04, the .deb and the AppImage, all fine.
- [ ] On each phone: **Sound** (it shows only when the share has sound: in Porthole's own window press **Open in my browser**, then share a tab with "Also share tab audio" on), pinch to zoom, drag to move around, double-tap to zoom back, turn the phone sideways, **Full screen**, and **Data saver**.
- [ ] **Ask before someone watches** (on by default): the phone waits, the PC shows the phone with **Allow** and **Deny**, and the short code on the phone matches the code on the PC. **Deny** one phone (it stays out for the rest of the run, even after **Try again**), and **Allow** another, or the same phone in a private tab.
- [ ] **The "waiting" notification with the default switches:** in a browser that has never shown Porthole's page (a new browser profile), press **Start sharing** (Ask is on). The browser asks whether Porthole may show notifications; say yes. Put the page in the background and let a phone join: a "1 waiting" notification shows. Stop and **Start sharing** again: no second question. In another new profile say no: it is never asked again (not even when Ask is turned off and on).
- [ ] **Two phones at once:** both waiting rows are told apart: two phones of the same kind are numbered ("Android phone 2"); different kinds by their name, code and join time.
- [ ] **Easy address:** turn it on, then type `porthole.local` on each phone (on Windows and macOS plain `porthole.local` works; on Linux add `:8765`). iPhone browsers other than Safari need **Local Network** allowed in the iPhone's Settings.
- [ ] **Easy address turned off while a phone watches by it:** with a phone watching by `porthole.local:8765`, turn **Ask** off (Easy address goes off with it). The phone keeps watching; turn its Wi-Fi off for 10 seconds and on again, and the picture comes back. **Stop sharing** and **Start sharing**: the phone gets the new share. A second phone that types `porthole.local:8765` now sees "Use the link". About two minutes after the first phone closes its tab, the name stops working (the second phone's browser can't find it).
- [ ] **Another name for the PC:** on a phone, open `http://<the PC's name>.local:8765/` (Ubuntu answers for its own name). It says "Use the link · Open the link or scan the QR code shown on the sharing PC.", not "Bad request", in Porthole's usual look (centred, dark in a dark theme), not as plain black text on white.
- [ ] **Wi-Fi drop:** with a phone watching, turn its Wi-Fi off for 10 seconds, then back on. Then lock the phone for 40 seconds and unlock it. The picture should come back by itself both times, and the sharer page lists the phone once, with the same name and code (not a second row such as "iPhone 2" with a new code). Try it on an iPhone (Safari) and an Android phone (Chrome).
- [ ] **A waiting phone that reconnects** (Ask on): let a phone wait without pressing **Allow**, lock it for a minute (or turn its Wi-Fi off for 10 seconds), then wake it. It shows the same code, the sharer page still has one waiting row for it, the tab title stays "(1) Porthole", and a screen reader doesn't hear "... wants to watch" a second time. **Allow** it: the picture comes. Reload the phone's page: it is still let in, in one row (with the same code only if it was back before Porthole noticed the old page closed, up to a second; often it gets a new code).
- [ ] **Paused while zoomed in:** on a phone watching, pinch to zoom into a corner of the picture. On the PC press **Pause**: a small "Paused" note shows at the top right of the phone's screen (not only the dark card), and stays put when you move the zoomed picture. A phone that joins while paused shows it too. **Resume**: the note goes. With VoiceOver or TalkBack on, "Paused" is read once, and "Watching" after Resume.
- [ ] **Home-screen shortcut:** add the viewer page to the home screen and open it from there, once with the easy address on and once with it off (it should open the share in both cases).

## The PC

- [ ] **Your real screen:** share through the system's picker. Try **Smooth motion** on and off.
- [ ] **Recording:** record about 60 seconds of a still desktop, stop, and open the folder. The file should play.
- [ ] **Recording while paused:** press **Pause**, then **Record**, wait a few seconds and press **Stop recording** before **Resume**. The page says "Nothing was recorded.", with no **Open folder**, and no new file is in the folder. Then **Resume**, **Record** for a few seconds, **Pause**, **Change** to another window and **Stop recording** before **Resume**: the page shows the part before **Change** as saved, with **Open folder**, and that one file is in the folder.
- [ ] **A full disk:** record to a nearly full USB stick (`--record-dir /media/<you>/<stick>`) until it fills. The page says "The recording stopped: the disk is full. What was recorded until then is saved.", the Saved line and **Open folder** show, and the file plays up to that point.
- [ ] **Stopping:** stop from the system's own "stop sharing" bar, then from Porthole's **Stop sharing**, then **Quit**.
- [ ] **App window:** closing Porthole's own window stops Porthole. **Open in my browser** moves the page to your normal browser.
- [ ] **Open in my browser keeps this run's choices** (best with Firefox as the default browser, which has its own saved settings): in Porthole's own window, let phone A in, deny phone B, turn **Smooth motion** on and **Easy address** off. Press **Open in my browser**. The browser tab shows the same switches; after **Start sharing** phone A watches without waiting again, and phone B, reloaded, is told it wasn't let in. In the browser tab, turn **Smooth motion** off. Quit, then start Porthole again with `--browser-tab`, so the browser tab is the run's first page (a plain start opens Porthole's own window first, and the tab would take that window's switches): it has its own saved Easy address back, with Smooth motion off (the run's switches were used for that run only; only the switch changed there was saved).
- [ ] **The waiting page's two lines:** with the sharer page open but not sharing, open `http://127.0.0.1:8765/share` in another tab: it says "Porthole is open in another window or tab.", its status line says "Open in another window or tab", and it has no Watching section. Press **Start sharing** in the first tab: within about 10 seconds the second says "Sharing is on in another window or tab." and its status line "Sharing in another window or tab" (with a screen reader, read once, not twice). **Use this one** works in both cases, and the Watching section comes back. Close the first tab: within about 15 seconds the second takes over by itself (its line and **Use this one** go, and **Start sharing** turns on), with this run's approvals and switches.
- [ ] **No sound note:** share a screen without sound in Firefox ("No sound is shared. This browser can't share sound."), in Chrome on Linux in a browser tab ("... pick a tab and turn on "Also share tab audio"."), and, on Windows, in Porthole's own window ("... pick a screen and turn on "Also share system audio"."); following the note gives sound in Chrome.
- [ ] **No network, then Wi-Fi:** turn Wi-Fi off (and unplug the cable), start Porthole: the page says "This PC has no network. Connect it to Wi-Fi or a network cable; the link shows here once it's connected." Turn Wi-Fi on: within about 20 seconds the link and the QR code show, without a restart, and a phone can watch.
- [ ] **Wi-Fi off and on while running** (from a terminal): with Porthole running, turn the PC's Wi-Fi off. Within about 10 seconds the terminal says "This PC has no network now, so other devices can't connect." Turn it on again: "Back on the network. Viewers (phone or PC): <link> (same link as before)", with the link it showed at start (not "The network address changed"). Join another Wi-Fi instead: "The network address changed. Viewers (phone or PC): <the new link>".
- [ ] **Open folder without xdg-utils** (Linux, from source on a PC without xdg-utils, or with `xdg-open` not on the PATH): after a recording, **Open folder** says "Couldn't open the folder. The recording is in <the folder>. Opening folders needs xdg-utils.", with no "[Errno 2]".
- [ ] **Porthole killed:** with the sharer page open (in a browser tab, then in Porthole's own window), end Porthole with `kill -9 <its process>` (Task Manager on Windows). Within a few seconds the page says "Porthole isn't running any more. You can close this page." and its buttons are off; Porthole's own window stays open with the note.
- [ ] **Porthole killed and started again:** with the sharer page open in a browser tab (`--browser-tab`) and a phone watching, end Porthole with `kill -9 <its process>` and start it again the same way. Within about 10 seconds of the new start, the old tab says "Porthole was restarted. Use its new page, or reload this one." (not "Porthole has stopped or restarted. Start it again and reload this page."), and the phone says "Ended · Porthole was restarted. Use its new link, or try again." With the easy address on, **Try again** on the phone opens the new share once it starts. In Porthole's own window, the old window closes once the new one opens.
- [ ] **A Change that fails** (hard to cause on purpose: try closing the picked window just as you press **Share**): while sharing with a phone watching, the page says "Couldn't change what's shared: …", and the phone keeps the picture it had. Pressing **Cancel** in the picker says nothing.
- [ ] **Mini controls** (Chrome or Edge): open them, press **Change**, and while the screen picker is open press **Stop sharing** in the mini window. Then pick a screen: sharing should stay stopped.
- [ ] **Firefox as the sharer.**
- [ ] **Theme:** Auto, Light and Dark look right on both pages.

## Keyboard and screen readers

The headless-Chrome test checks names, focus and announcements; these need real assistive technology. For each, note what is read out and anything read twice or not at all.

- [ ] **Keyboard only on the PC** (no mouse): Tab through the sharer page in both themes; every control shows a ring. Start sharing, Pause, Record, Stop sharing, the theme switch (arrow keys), the three switches (Space), Allow and Deny for a waiting phone, Deny all, Copy, Other addresses, Quit. Focus never jumps back to the top.
- [ ] **Keyboard only on a PC viewer:** press + to zoom in (1:1 shows only when the picture is bigger than the window, so use a normal-density screen or a small window to try it), Tab to 1:1 and press Enter; the arrow keys reach every corner of the shared screen, + and - zoom, and 1:1 or Fit goes back. On the quality menu the arrow keys change the quality and don't move the picture.
- [ ] **NVDA on Windows** (Porthole run from source; Chrome or Edge, then Firefox): with Ask on, a phone joins: "Android phone wants to watch. Code 482." is read once, not every few seconds. Start sharing first ("Sharing" is read), then Allow it by keyboard: focus lands on its row under Watching, read as "Android phone, code 482, Connecting", then the row says Watching (note whether that change is read), and it stays quiet while it is watched. Stop sharing: "Not sharing" is read. Share a whole screen, stop, then share a whole screen again: the notifications note is read both times. Turn Easy address on and off: the switch is read with its line; with the easy address unable to start (port 5353 taken), its error is read a moment after "on". Press Copy: "Copied" is read once.
- [ ] **Orca on Linux** (Chrome or Firefox): the same as NVDA.
- [ ] **VoiceOver on a Mac** (Porthole run from source; Safari as a viewer, Chrome as the sharer): the same, plus the mini controls window: a phone joining is read there too.
- [ ] **VoiceOver on iPhone** (Safari): with the PC sharing, open the viewer link. "Waiting. Ask the sharer to let you in. Your code: 482" is read; after Allow, "Watching". Then try to reach the buttons (Sound, 1:1, Pop out, Save, quality, Full screen) once they have hidden: double-tap the picture to bring them back, swipe to them, and see whether they stay while VoiceOver is on one. Turn the phone sideways.
- [ ] **TalkBack on Android** (Chrome): the same as VoiceOver on iPhone.
- [ ] **Zoom:** the sharer page at 200% browser zoom, and the phone's largest text size on the viewer's waiting screen: nothing is cut off and nothing needs sideways scrolling.
- [ ] **"Nothing shared yet"** with a screen reader on a phone: type the easy address before Start sharing. The page should stay quiet (not be read out again every 5 seconds) and open the share once it starts.

## Ubuntu packages

- [ ] **Ubuntu:** the snap (`snap install --dangerous` on the built file until it's in the store), the .deb and the AppImage. Each opens from the app menu, and a phone can watch. The .deb and the AppImage done 23 Nov 2026 (Ubuntu 26.04, an Android phone and an iPhone: all fine); the snap still to do.
- [ ] **An older menu entry:** with the .deb not installed, run `./Porthole-x86_64.AppImage --install-launcher`, then install the .deb. The menu's Porthole still starts the AppImage. Run `porthole --install-launcher`: it says "Removed an older Porthole menu entry; the package's own entry stays.", and the menu's Porthole now starts the .deb's (`ps -ef | grep /usr/share/porthole` while it runs). Run it again: "Porthole is already in your app menu."
- [ ] **Snap notices:** with the .deb's Porthole running, start the snap's from the app menu. It takes over, and a notification says "Stopped the Porthole from /usr/share/porthole and started this one." (before, the snap's notices didn't show at all).
- [ ] **Two installs:** start the .deb's Porthole (or the snap's) from the app menu and share with a phone watching. Then start the AppImage from a terminal, without `--port`. The first Porthole stops (its app window closes, or its browser tab says it stopped; the phone sees the share end), the terminal says "Stopped the Porthole from /usr/share/porthole and started this one." (the snap's folder is under `/snap/porthole/`), and the new page shows port 8765. Start the AppImage again from its menu entry or a terminal: it only opens the running page, nothing restarts. Started from the menu instead of a terminal, the "Stopped the Porthole..." line shows as a notification.
- [ ] **Something else on 8765:** in a terminal run `python3 -m http.server 8765`, then start Porthole without `--port`. The terminal says "Port 8765 is busy, so Porthole uses port 8766."; the page, the link, the QR code and the easy address show 8766, and a phone can watch. Stop it, then start it with `--port 8765`: it says "Port 8765 is already in use. Try: <command> --port 8766" with the right command (`porthole` for the .deb and the snap, the AppImage's file, `python3 start.py` from a folder) and doesn't start. To check the snap's hint with the .deb also installed, start it as `/snap/bin/porthole --port 8765`.
- [ ] **Snap removed while it runs:** start the snap's Porthole from a terminal (`/snap/bin/porthole`: with the .deb installed too, plain `porthole` starts the .deb's), then `sudo snap remove porthole` in another one. Within about 5 seconds it should stop with "Porthole can't accept connections any more, so it stopped." (or end at once with the removal) and not keep a CPU core busy (watch `top`). Then the AppImage started without `--port` gets port 8765.

## Windows and Mac, from source

The Windows installer and the Mac disk image are parked on the `archive/windows-macos` branch of the private repository, with their own checks. Until they come back, these run Porthole from source.

- [ ] **Windows** (`py start.py`): Windows Firewall asks about Python; allowed on **Private** and **Public**, a phone can watch on a network Windows calls "Public". On a PC with WSL, Hyper-V, VirtualBox or VMware, the sharer page lists only the real Wi-Fi or Ethernet address. Porthole opens in its own Chrome or Edge window, and closing it stops Porthole.
- [ ] **Mac** (`python3 start.py`): allow screen recording (note whether macOS names the browser or Terminal), and the local network when asked. A phone can watch. Closing Porthole's window stops it, and the Chrome it started quits.

## Networks

- [ ] **Phone hotspot:** connect the PC and another phone to one phone's hotspot and watch.
- [ ] **Guest or office Wi-Fi** that keeps devices apart: the phone can't open the page. The README's troubleshooting should lead you to the hotspot, and the hotspot should work.
